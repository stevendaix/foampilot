# Patient 58 CFD Pipeline — Complete Workflow

## Overview
End-to-end pipeline for patient 58 aortic CFD simulation in OpenFOAM 13, from STL processing through to steady-state flow solution. Validated with `checkMesh` and `simpleFoam` (100 iterations, converged).

## Key Problems Encountered & Solutions

### 1. STL Normal Orientation Issues
**Problem**: The medical STL (`tbad_TL_walls.stl`, 260,560 triangles) extracted from NIfTI has inconsistent triangle winding. `trimesh.is_watertight` is unreliable — returns `True` but `contains()` reports centroid as outside mesh. `auto_orient_normals` in pyvista only ensures consistency between adjacent faces, not outward direction.

**Solution**: Don't process or flip normals. Use the original STL (scaled to meters). snappyHexMesh's own algorithms handle normal orientation correctly. Use `locationInMesh` at a point that trimesh's `contains()` confirms is inside.

**Working command for STL prep**:
```python
import trimesh
m = trimesh.load(stl_path, process=True)
if not isinstance(m, trimesh.Trimesh):
    m = m.dump(concatenate=True)
m.vertices *= 0.001  # mm to m
m.export('constant/triSurface/tbad_TL_walls.stl')
```

### 2. LocationInMesh Point Selection
**Problem**: The centroid may be outside the lumen due to STL topology issues.

**Solution**: Use the centerline midpoint. Extract a point that trimesh's `contains()` confirms is inside:
```bash
cl = np.load('centerline.npy') * 0.001
# Use cl[len(cl)//4] — the 25% point, verified inside by trimesh.contains()
locationInMesh (0.229 0.222 0.049);  # centerline 25% point in meters
```

### 3. Three Boundary Patches from Single STL
**Problem**: Need INLET, OUTLET, and WALL patches but snappyHexMesh produces one wall_aorta patch. Using 3 STL files (wall + inlet/outlet caps) fails because STL normals are inconsistent at shared edges.

**Solution**: Post-process the snappyHexMesh-generated mesh:
1. Run snappyHexMesh with single STL → get wall_aorta patch
2. Use Python to read `constant/polyMesh/points`, `faces`, `boundary`
3. Compute wall_aorta face centroids, split by z-coordinate
4. Reorder faces: [INLET faces] [OUTLET faces] [WALL faces]
5. Rewrite `faces`, `owner`, `boundary` files with new patch ordering

### 4. OpenFOAM 13 Syntax Changes
**Problem**: OF13 renamed several utilities and changed dictionary syntax.

**Solutions**:
- `simpleFoam` now runs `foamRun -solver incompressibleFluid` internally
- `fvSolution` requires `PIMPLE` (not `SIMPLE`) with explicit `UFinal`/`pFinal` solver entries
- `createPatch` uses `constructFrom set` instead of `constructFrom namedSet`
- `createPatch` uses `patchInfo { type patch; }` for patch type specification
- `fvSchemes` no longer recognizes `div(phi,(nu_eff ...))` — use `div(phi,nuEff)` and `div(phi,R)`

### Step 3: Split Patches (Python Script)
```python
import numpy as np, re

# Read mesh files
points = read_of_points('constant/polyMesh/points')
faces = read_of_faces('constant/polyMesh/faces')
owner = read_of_labels('constant/polyMesh/owner')

# Get wall_aorta face IDs from boundary file
wa_start, wa_n = parse_boundary('constant/polyMesh/boundary')['wall_aorta'][:2]

# Compute centroids and split by z-coordinate
wa_ids = list(range(wa_start, wa_start + wa_n))
centroids = np.array([np.mean(points[faces[fid]], axis=0) for fid in wa_ids])
zmin, zmax = centroids[:,2].min(), centroids[:,2].max()
z_range = zmax - zmin

inlet_ids = [wa_ids[i] for i in range(len(wa_ids)) if centroids[i,2] <= zmin + z_range * 0.10]
outlet_ids = [wa_ids[i] for i in range(len(wa_ids)) if centroids[i,2] >= zmax - z_range * 0.10]
wall_ids = [wa_ids[i] for i in range(len(wa_ids)) if inlet_thresh < centroids[i,2] < outlet_thresh]

# Reorder: prepend INLET+OUTLET+remaining WALL after internal faces
perm = list(range(wa_start)) + inlet_ids + outlet_ids + wall_ids
new_faces = [faces[p] for p in perm]
new_owner = [owner[p] for p in perm]

# Write faces, owner, boundary files
# INLET: start=71073, nFaces=376
# OUTLET: start=71449, nFaces=2512
# WALL: start=73961, nFaces=7705
```

Final mesh: INLET (376), OUTLET (2512), WALL (7705), 25,585 cells.

## Lessons Learned

### Don't Process STL Normals
- `trimesh.invert()`, `fix_normals()` with centroid check, and pyvista `auto_orient_normals` all fail on medical STLs
- snappyHexMesh handles inconsistent normals internally — use original STL
- `trimesh.contains()` is unreliable for medical STLs (use centerline points only)

### Refinement Level 3 3 Required
- Level (2 2): Mesh covers only z=0.037-0.060 (misses inlet at z=0.003)
- Level (3 3): Mesh covers full STL z-range 0.003-0.060

### nCellsBetweenLevels 4
- Default value of 2 causes coarse transition between refinement levels
- Setting to 4 improves mesh quality near STL surface

### OF13 fvSolution Requirements
- Must use `PIMPLE` section (not `SIMPLE`)
- Must define `pFinal` and `UFinal` as separate solver entries at `solvers` level
- `UFinal` and `pFinal` need to be sibling entries to `p` and `U`, not nested inside them

### Face Reordering for Patch Splitting
- Must reorder `faces` AND `owner` arrays together using the same permutation
- `neighbour` file is unchanged (only covers internal faces that stay in same positions)
- Boundary file needs correct `startFace` and `nFaces` for each new patch
