# Audit OF13 — multiRegion/CHT/coolingSphere

Le chemin `multiRegion/CHT/coolingSphere/templates` listé dans la matrice est un répertoire de gabarits non exécutable isolément : il ne contient ni `Allrun`, ni `controlDict`, ni `blockMeshDict`. Le cas exécutable de référence est son parent `/opt/openfoam13/tutorials/multiRegion/CHT/coolingSphere`, dont l’Allrun appelle `Allmesh`, `foamSetupCHT`, `foamDictionary`, `decomposePar -allRegions`, `foamMultiRun` parallèle et `reconstructPar -allRegions`.

La préparation parent exécute `blockMesh`, `createZones`, `transformPoints scale=(0,01 0,01 0,01)` et `splitMeshRegions -cellZones -defaultRegionName fluid`. Les templates fournissent les champs initiaux régionaux `fluid/solid`, les systèmes régionaux et les matériaux `air`, `water`, `aluminium`, `copper`. `foamSetupCHT` lit `constant/materialProperties`, génère les répertoires régionaux et écrit `regionSolvers`; le champ `0/solid/T` est ensuite réglé à `uniform 348`. Le contrôle source fixe `endTime=1`, `deltaT=5e-4` et écriture toutes les `0,05` unités.

Le runner `172_multiRegion_CHT_coolingSphere/run.py` importe via FoamPilot le cas parent et l’arborescence `templates`, exécute toutes les étapes de l’Allrun avec `solver.run_command`, et lance `foamMultiRun` à quatre domaines. Une première validation a révélé que `foamSetupCHT` attend explicitement `templates/materials/air`; l’arborescence templates complète a donc été conservée dans le cas cible. La validation corrigée génère les matériaux air/cuivre, décompose les régions, atteint `Time=1 s` et `End`, puis la reconstruction régionale s’exécute sans `FOAM FATAL`. Aucune nouvelle API nécessaire.
